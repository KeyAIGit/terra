# TERRA — контекст для Claude (Cowork / Claude Code)

Симулятор цивилизации с субагентными людьми + игровой слой. Владелец: Bekzad.
Курс: игра-перемещение по эпохам, 3D, путь к фотореализму через UE5.
Роли: Фейбл (Claude) — весь код, симуляция, данные, игра; пользователь — аккаунты, UE на Mac (M3 Max).

## Что это

- `terra/` — пакет Python 3.11 (только numpy/scipy/Pillow; three.js вшивается в HTML).
- Мир детерминирован сидом: код + сид = тот же мир до последнего имени. Бинарники
  прогонов НЕ нужно хранить — они воспроизводятся (полный прогон до 500 н. э.:
  ~2.5 ч в облачном контейнере кусками, на M3 Max заметно быстрее).
- Онлайн-витрина мира: https://bekzod25-terra-world.static.hf.space/
  (двойник настоящего: /twin.html — сборка --split, выкладывать
  huggingface_hub'ом с токеном из terra-secrets; через MCP не выйдет,
  содержимое не влезает в вызов)
  (HF Space Bekzod25/terra-world; тяжёлые страницы на CDN; сейчас там мир terra-1,
  пересобрать из terra-life после доводки до 2100).
- Секреты (GitHub PAT, HF write-токен) — в приватном HF-репо Bekzod25/terra-secrets
  (github.md; hf_token.md в base64). В публичный репозиторий не класть.

## Команды

```bash
python3 -m tests.test_terra --slow    # обязательно после правок ядра
python3 -m terra new --seed 1 --to 500 --name terra-life
bash runrobust.sh terra-life 500 1    # то же кусками (контейнер убивает фон >40 мин)
bash steploop.sh terra-life 2100      # доводка ПОСЛЕ 500: step.py чекпоинтит по бюджету
python3 -m terra doctor terra-life    # самопроверка физики и целостности
python3 -m terra.export_ue runs/terra-life   # пакет для UE (51 самопроверка)
python3 -m terra.play runs/terra-life        # игра-прогулка (play.html)
python3 -m terra multiverse           # реестр всех миров на диске
```

ВАЖНО: после 500 н. э. НЕ гонять `terra continue` в контейнере — при населении
200 млн+ он не доживает до чекпоинта (500-летний шаг чекпоинта > 40 мин) и
убивается без следа. Только step.py/steploop.sh.

## Грабли, на которые уже наступали (НЕ повторять)

1. Истощение почвы без восстановления → мир откатывался к собирательству.
2. Тупики аффордансов: тест «весь каталог достижим» ловит.
3. Прибавочный продукт ≠ незанятая ёмкость.
4. Любой обход set по клеткам — ТОЛЬКО отсортированный.
5. Никаких кэшей в атрибутах класса.
6. Летопись: вес события масштабировать от населения.
7. Обрушения держав — с периодом восстановления 450 лет.
8. ПЕРЕГРЕВ ПРОЖИТОЙ ЖИЗНИ (найден A/B-прогоном, вылечен, НЕ откатывать):
   a) вклад шрама голода в intensify/store центрирован по народу (иначе каждый
      голод разгоняет демографию: было 896 млн к 500 н. э. вместо 178);
   b) качество искателя 0.30·craft+0.30·max+0.20·lore — средний ≈ 0.4, как
      старый beta(2,3); при 0.5/0.5/0.35 искатели насыщались и открытия шли
      на треть чаще;
   c) потолок прироста r_cap открывается только НАСТОЯЩЕЙ медициной
      (health > 1.3): домодерная гигиена сама набирает ~1.2, и без порога
      бронзовый век растёт как двадцатый.
   Методика: A/B мини-миром против старого коммита — cfg из tests/test_sim_short
   + seed_polities 60 + печать каждые 500 лет; после Sim(cfg) НЕ забывать
   s.seed_world().
9. Пейсинг новой эры — открытый вопрос: в v3 паровая машина в −246 (Земля +1780),
   внутренние интервалы почти земные (до ядра −132), машинный разум к 500 не
   открыт (гейт 2e7 связанных душ держит). Если тюнить — диффузию/гейты знаний,
   НЕ демографию.

## Твин: цифровой двойник настоящего (twin/, ПОСТРОЕН — фаза 1)

Симуляция настоящего для реальной территории; первый регион — Залив
Сан-Франциско, первая сцена — город СФ. От слепка настоящего строим слои
назад во времени (2026 → 1950 → 1906 → 1849 → 1776 → до-колониальный) до
смычки с симуляцией TERRA. Стратегия: docs/twin_strategy.md.

```bash
python3 -m twin.keys                   # какие ключи есть, где взять недостающие
python3 -m twin.ingest --budget 1500   # резюмируемый сбор (манифест twin/data/manifest.json)
python3 -m twin.doctor                 # схема parquet + физика (Твин-Пикс, Трансамерика…)
python3 -m twin.build sf               # scene_sf.json.gz из данных
python3 -m twin.view sf                # twin_sf.html — офлайн-файл целиком
python3 -m twin.view sf --split site   # для хостинга: оболочка 6 КБ + данные рядом
python3 -m tests.test_twin             # офлайн-проверки твина
```

Источники (все БЕЗ ключей): Copernicus GLO-30 (рельеф; DSM — в фазе 2
заменить центр города на USGS 1 м DTM), DataSF ynuv-fyni (177k контуров
зданий с лидарными высотами) + wv5m-vpq2 (реестр оценщика: ГОД ПОСТРОЙКИ
каждого участка — работающая машина времени), OSM Overpass (именованные
здания, дороги, вода, зелень, POI), Census cb_2023 (9 округов), NOAA
(погода), KartaView (уличная съёмка с курсом камеры, CC BY-SA), Викисклад
(геопривязанные виды зданий). Данные twin/data/ в gitignore — воспроизводятся манифестом.
Дисциплина атласа: провенанс source/license/tier/retrieved, ярус K.

МАШИНА ВРЕМЕНИ РАБОТАЕТ (слайдер года 1791–2026): 165k зданий с годом,
фильтр в вершинном шейдере (uniform uYear; схлопывание вершин в точку) —
175k зданий передатируются на кадре. Именованные здания OSM наследуют год
от лидарных контуров, попадающих ВНУТРЬ их многоугольника (по bbox нельзя —
затягивает год соседа). Сверено с жизнью: Трансамерика 1972, Salesforce 2018,
Койт-Тауэр 1933, 555 California 1969 — проверяется в twin.doctor.

СЕНСОРЫ И ЖИВОЙ СЛОЙ (клавиши 1-4: оптика/ПНВ/тепловизор/ЭЛТ). Тепловизор
НЕ красит яркость картинки: считает температуру поверхности по альбедо и
тепловой инерции материала, углу падения солнца, запасённому за день теплу
и собственному теплу здания по назначению; воздух — из живого наблюдения
NOAA. Шкала в °C. Материал каждой поверхности едет атрибутом aMat
(0 земля, 1 зелень, 2 песок, 3 вода, 4 асфальт, 10+назначение — здания);
sensorized() дополняет материал через onBeforeCompile, НЕ подменяя его —
иначе ломаются инстансы и фильтр года. Пост-обработка — свой мини-композер
на рендер-таргете (EffectComposer живёт в examples/jsm, ядро three его не
несёт). twin/sources/live.py: борта adsb.lol, спутники CelesTrak+sgp4
(pip install sgp4; без него источник честно пропускает только спутники),
толчки USGS, прилив NOAA CO-OPS 9414290 -> реальный уровень воды в заливе,
камеры Caltrans D4 (кадры отдаются с Access-Control-Allow-Origin: *, поэтому
живой снимок дороги грузится прямо в офлайн-страницу).

АЭРОФОТОПОДЛОЖКА: twin/sources/imagery.py тянет NAIP 0.6 м (общественное
достояние, БЕЗ ключей) мозаичными тайлами Planetary Computer (z16, ~1000
тайлов -> JPEG 4096). Тайлы в Меркаторе, а сетка рельефа ровная по широте —
UV считаются с поправкой mercY, иначе фото сползает на десятки метров.
Под фотографией ленты дорог прячутся (улицы уже сняты), а при уходе в
прошлое снимок выключается с пояснением: он показывает СЕГОДНЯШНЮЮ землю.
view.py --tex N ограничивает ширину снимка (для встраивания брать 2048),
--fragment даёт страницу без обёртки.

ПРОГНОЗЫ (twin/forecast.py): issue выпускает датированные проверяемые
предсказания, score сверяет их с тем, что вышло — точечные по средней
ошибке, вероятностные по Бриеру. Правило: прогноз без записи ДО и сверки
ПОСЛЕ ничего не стоит. Три предсказателя без ключей: прилив (гармоника NOAA
— проверяется за часы, поэтому на нём отлаживается вся петля), температура
(NWS), сейсмика (Гутенберг—Рихтер, b по Аки; на живом каталоге b=1.00,
P(M>=5 за год)~43% — в коридоре USGS). ЧЕСТНО: поток пуассоновский, афтершоки
не расцеплены, короткие горизонты завышены — это записано в самом прогнозе,
и оценка Бриера это покажет.

УЛИЧНАЯ СЪЁМКА И ПОВЕРКА ФОТОГРАФИЕЙ (twin/sources/streetlevel.py): настоящие
кадры тех же улиц БЕЗ ключей — KartaView (съёмка с регистраторов, CC BY-SA,
точка + КУРС камеры + дата) и Викисклад (геопривязанные виды, свободные
лицензии). Кадры НЕ перекладываем к себе: в parquet едет только адрес, автор
и лицензия, картинку страница берёт с первоисточника. Смысл слоя — поверка:
кнопка «встать сюда» ставит камеру ровно в точку съёмки и разворачивает по
курсу кадра, «идти следом» держит рядом ближайший снимок, снятый в ту же
сторону (±55°, до 250 м). Дальше глаз сравнивает сам: что стоит, чего нет,
что не той высоты. Курс — не украшение: кадр без курса сравнивать не с чем,
поэтому doctor требует курс у >=90% кадров, а в собранной сцене — строго
внутри [0, 360). Прореживание: KartaView отдаёт ~4000 кадров на радиус 450 м
(регистратор в пробке снимает один бампер сотню раз) — оставляем свежий кадр
на 22 м при сборе и на 45 м в сцене. ГРАБЛИ: у KartaView нет CORS, поэтому
кадр годится в панель <img>, но НЕ в текстуру WebGL; Викисклад с
generator=geosearch отдаёт координаты только первым десяти страницам, пока не
попросишь colimit=max; курс округляем ДО приведения к кругу, иначе 359.97
превращается в 360.0 уже после нормировки.

GOOGLE MAPS PLATFORM (слои за ключом ПОЛЬЗОВАТЕЛЯ, twin/_view_js.py): три
продукта Гугла, все требуют ключ и включённый счёт. Street View Static — кадр
из той же точки и в ту же сторону, где стоим (рядом с нашей геометрией, для
прямого сличения). Map Tiles 2D satellite — вид сверху: плитки сшиваем в
полотно и подкладываем вместо NAIP (UV рельефа уже с поправкой Меркатора,
поэтому ложится без сдвига), сеанс берётся через createSession. Photorealistic
3D Tiles — фотореалистичная прогулка: свой обходчик дерева 3D Tiles (тащить
Cesium ради одного слоя дороже, чем написать обход), плитки приходят в ECEF и
переводятся в сцену матрицей «геоцентр -> восток/верх/юг», посчитанной по
центру сцены; материал каждой плитки пропускается через sensorized(), поэтому
тепловизор и ПНВ работают и по фотограмметрии. GLTFLoader и DRACOLoader живут
в examples/jsm модулями ESM — twin/view.py переписывает их в обычный скрипт
(каждый модуль в своём замке, иначе `const {Loader} = THREE` объявится
четырежды), декодер Draco вшит как data:URI и отдаётся через
setDecoderPath({js, wasm}). КЛЮЧ: вводится в браузере, лежит только в
localStorage, уходит одному Гуглу; doctor ищет в исходниках и сцене строку
вида AIza… и валит сборку, если найдёт. В репозиторий ключ не класть.
НЕ ПРОВЕРЕНО ЖИВЬЁМ: ключа у нас нет, поэтому все три слоя Гугла написаны, но
не запускались — ошибки они показывают в панели вслух. Бесключевые слои
(KartaView, Викисклад) проверены Playwright'ом.

ЛЮДИ: население только СИНТЕТИЧЕСКОЕ из агрегатов переписи (TIGER POP20 без
ключа), расселяется по реальным зданиям; ни один житель не соответствует
живому человеку. Поимённо реальных жителей и должностных лиц НЕ моделируем
и слов им не приписываем.

НАСЕЛЕНИЕ И ЖИТЕЛИ: twin/sources/population.py — TIGER TABBLOCK20 (без ключа,
поле POP20): 63 719 кварталов, 7 765 640 человек по девяти округам — точное
число переписи 2020. twin/people.py расселяет население квартала по реальным
зданиям соразмерно жилому объёму (площадь x высота x доля жилья по назначению
участка) и порождает жителей: по сцене СФ 888 124 человека при реальных
873 965, медианный возраст 39 против настоящих 38.3. Сид из номера квартала —
один квартал всегда даёт тех же людей. ЯРУСЫ: население квартала K
(измерено), параметры распределений T (типично для места), сам житель R
(реконструкция). Проверяется в twin.doctor, включая запрет на имя у
синтетического жителя.

ГОЛАЯ ЗЕМЛЯ (twin/sources/bareearth.py, БЕЗ КЛЮЧА): USGS 3DEP Bare Earth через
ArcGIS ImageServer (elevation.nationalmap.gov). Copernicus GLO-30 — модель
ПОВЕРХНОСТИ: она меряет то, от чего отразился радар, то есть крыши, и в центре
города «земля» поднята на высоту застройки. 3DEP отдаёт землю с вычтенной
застройкой, шаг 3.9×4.6 м вместо 30 м. Сцена режется на 2×2 плитки по 2000×1600
(заявленный потолок 8000 не выдерживает: крупный вырез отваливается 500).
build.py сам предпочитает bare_<key>.npz, если он собран, и ТОГДА НЕ ПРИМЕНЯЕТ
минимум-фильтр — на голой земле он срезал бы настоящие гребни холмов. Поверка в
doctor: высшая точка сцены 287 м (Твин-Пикс, в жизни 282), деловой центр 4.8 м
(у GLO-30 там 7.2 — это крыши).

КЛЮЧИ (twin/keys.py, docs/twin_keys.md): реестр 16 поставщиков — что даёт,
где брать, сколько стоит, нужна ли КАРТА. Из 16 карту требуют ровно два
(Google Maps Platform и Anthropic), остальные 14 выдают ключ за почту.
Хранение: переменная окружения либо twin/.keys.json (в .gitignore, права 600);
браузерные ключи вводит зритель на странице, они живут в его localStorage.
В ПЕРЕПИСКУ КЛЮЧИ НЕ ПЕРЕДАВАТЬ — она пишется в журнал сессии; путь для
облачной сессии: заполненный бланк (--template) в приватный репозиторий
Bekzod25/terra-secrets как twin_keys.json, оттуда python3 -m twin.keys --pull-hf
с HF_TOKEN из окружения. doctor обыскивает исходники, сцену и готовый HTML на
шесть видов ключей и валит сборку при находке, а также спрашивает git,
действительно ли .keys.json игнорируется.

ГРАБЛИ ХОСТИНГА НА HF (стоили часа): страница ОТКРЫВАЕТСЯ в браузере, только
если HF отдаёт её напрямую (HTTP 200, content-type text/html). Файл, ушедший
в LFS/Xet, отдаётся редиректом на CDN — браузер такое СКАЧИВАЕТ. Причины две:
(1) huggingface_hub при загрузке файла тяжелее ~10 МБ САМ дописывает правило
в .gitattributes (у нас появилось `twin_sf.html filter=lfs`), и путь остаётся
редиректным даже после снятия правила и перезаливки — нужен ЧИСТЫЙ путь
(взяли twin.html); (2) расширение .gz попадает под общее правило *.gz — файл
сцены назвали twin_sf.scene, содержимое всё равно gzip, обозреватель узнаёт
его по подписи 1f 8b в первых байтах.
Решение целиком: `python3 -m twin.view sf --split КАТАЛОГ` — оболочка 6 КБ
(CSS+разметка), three.js и приложение отдельными .js, сцена и снимок рядом.
На <script src> и fetch редирект не влияет, CORS у CDN открыт (*), но картинке
нужен crossOrigin='anonymous', иначе WebGL не возьмёт её в текстуру.
Живой адрес: https://bekzod25-terra-world.static.hf.space/twin.html

Грабли твина: Overpass троттлит (зеркала чередуем, массовую застройку
берём НЕ из него, а из DataSF); Census API теперь требует ключ (население
без ключа — TIGER TABBLOCK20, поле POP20); GLO-30 — поверхностная модель, поэтому
под сценой её сменила голая земля 3DEP (bareearth); минимум-фильтр 3×3 остался
только для регионов, где 3DEP не собран; сайт SFEI (до-колониальный
ландшафт) 403-блокирует наш прокси — качать на стороне пользователя.
ГРАБЛИ ДАТИРОВКИ: оценщик пишет 1900 вместо «неизвестно» (14.5k участков
против 161 в 1901) — не считать это датой; весь центр датирован 1906+ из-за
пожара (нужны карты Сэнборна); 11k зданий вообще без года — показываются
по умолчанию, гасятся галкой, чтобы игрок видел объём незнания.
THREE.ShapeUtils.triangulateShape МУТИРУЕТ входной контур — триангулировать
копию, иначе стены читают за границей массива.
